Autonomous negotiation for the Causa Prima hackathon. Python workers buy, sell and negotiate while a shared ledger and explicit guardrails gate every game action.

This is a map of the implemented system and its declared deployment. It does not report current uptime, enabled feature flags or game standings. Source links below identify the code behind each part.

01 / The trading loop

Read → decide → check → act

The organisers’ API owns the clock, inventory and settlement. Workers respond to game ticks; they share one team key and one action budget.

  1. 01

    Read the game

    Clock, holdings, available dealers and venue books form the current snapshot. The monitor archives the event stream and fills gaps from the feed.

    Snapshots · Monitor
  2. 02

    Choose a move

    Taker and maker policies rank trades and manage conversations. Duel policies negotiate their own price and delivery terms. Jev or the configured LLM supplies advisory verdicts.

    Taker · Maker · Duels
  3. 03

    Pass the gates

    Validate the structured action against inventory, guardrails, approvals, breakers and the remaining tick window. The shared Postgres ledger coordinates accepts and listings.

    Guardrails · Shared ledger
  4. 04

    Send and record

    Python sends approved actions through the game client, backed by the vendored SDK. The organisers settle accepted trades on the next tick. Decisions and execution outcomes are recorded.

    Game client · Decision records · Official rules

↩ Outcomes return through the game feed and fresh inventory reads, updating memory for the next decision.

02 / Reasoning paths

Policies, verdicts and operator tools

Autonomous loops and the interactive desk have different entry points. Model output informs choices; validated Python actions own execution.

Autonomous workers

Trading and duel policies run on game ticks. A configurable Jev/LLM decider advises under a bounded budget; short ticks can fall back to Jev. Optional generated words do not replace structured prices.

Decider · Runtime settings

Interactive desk + MCP

The Claude Agent SDK desk routes operator requests to strategist, buyer, seller and duelist roles. CLI and authenticated MCP tools use the same Python actions and guardrails; writes default to dry run.

Desk · Write actions · MCP server

Feed learning + recall

Feed and thread readers extract counterparty behaviour and outcomes. Optional LLM interpretation and local embeddings add context for future decisions; learning scopes keep duels and trading separate.

Learner · Recall · Settings

04 / State and feedback

Shared memory, separate records

Postgres is shared by the trading processes and referenced by the Railway partial; the partial does not create or manage that database service.

Operational state

Postgres stores holdings, feed history, traders, decisions, executions, approvals and the action ledger. The CLI monitor uses SSE plus feed polling; agents also read the market through their runtime.

Database schema · Holdings · Monitor

Memory for decisions

Learnings retain their evidence and scope. Retrieval can combine text search with local fastembed vectors when pgvector is available. The simulator keeps its world in a separate database.

Learning store · Embeddings · Simulator store

Logs + observability

Decisions and executions are inspectable records, with local JSONL fallbacks for supported logs. Per-service volumes hold local state and PAUSE files; Phoenix receives traces. A local log does not replace shared write coordination.

Decision log · Telemetry · Observability guide
05 / Safety boundaries

A proposal is not permission

Money and inventory

GUARDRAILS.md is the checked-in policy source for holdings protection, price limits and approval thresholds. Actions recheck inventory and refuse moves that fail their gates; model verdicts cannot grant an override.

Policy · Approvals

One team budget

Every process shares the game key and its request limits. Game ticks set deadlines; the ledger coordinates action quotas across machines. Local PAUSE files stop writes for the processes using that data directory.

Tick runtime · Ledger · Service contracts

Public vs privileged

Agent status endpoints expose a redacted view. Runtime tools require authentication, approvals have a separate privilege, and counterparty messages remain untrusted data. Live mode is an operator-controlled setting.

Status server · MCP boundary

Test without the live game

Python + Postgres
